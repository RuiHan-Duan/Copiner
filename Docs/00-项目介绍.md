# 项目介绍 — Copiner

## 项目定位

Copiner 是面向企业非代码工作的本地优先 AI Agent 桌面工具。员工只与一个 Agent 协作，由它在安全边界内协调模型、知识、自动化和企业系统。

项目本体不是单一聊天框，而是可移植的 Harness：全局 Agent、场景 Skill、动态 Hook、闭环 Workflow、审批禁令和纯文本 Memory。模型和外部系统是可替换适配器。

## 品牌与体验原则

- 产品名称以 `Copiner` 原字为准，不推导未经确认的词源或架构隐喻；
- 品牌识别来自定制大写 `C` 与 `Copiner` wordmark，应用图标和 Desktop 共用同一字形；
- Desktop 使用浅色工作面、深蓝灰文字、钴蓝强调与浅蓝阴影，运行状态同时通过文字和结构表达；
- 本地优先、敏感路由和审批边界由产品文案与真实状态明确说明，不依赖图形寓意。

## 总体架构

```text
┌─────────────────────────────────────────────────────────┐
│ Desktop：Layout / Conversation / TaskFlow / Harness UI   │
├─────────────────────────────────────────────────────────┤
│ DesktopHost：Tauri 生命周期、命令与本地适配                │
├─────────────────────────────────────────────────────────┤
│ CoreEngine：Workflow / Policy / Provider / Tool / Harness│
├─────────────────┬───────────────────────┬───────────────┤
│ Providers（待接入）│ Tools（待执行器）       │ 文本 Harness    │
├─────────────────┴───────────────────────┴───────────────┤
│ 同步与鉴权协议（待专项评审）                               │
├─────────────────────────────────────────────────────────┤
│ WorkspaceService：RAG / Memory / Queue / Gateway（未配置） │
└─────────────────────────────────────────────────────────┘
```

## 运行时和配置边界

| 边界 | 类型 | 职责 | 不负责 |
|---|---|---|---|
| `Desktop/` | WebView | 本地任务输入、阶段、事件、Todo/Plan、Harness 导航 | 领域判断、密钥、企业连接 |
| `Crates/DesktopHost/` | 本地 binary | 窗口、Workflow snapshot 命令与系统适配 | 重写 Workflow 和审批规则 |
| `Crates/CoreEngine/` | Rust library | 状态机、敏感路由、Tool/Harness 注册 | UI、网络、厂商 SDK、存储 |
| `WorkspaceService/` | 独立 binary | 未来云上/内网能力边界 | 当前不监听端口或访问数据 |
| `Skills/` | Markdown | 场景流程、输入输出、审批点和禁令 | 工具执行 |
| `Hooks/` | JSON/schema | 动态上下文来源声明 | 自动授权或绕过路由 |
| `Memory/` | Markdown | 可审阅、可迁移的长期信息 | 不可见的模型记忆 |
| `References/` | 文档/索引 | Skill 按需加载的重资料 | 生产数据仓库 |

## 代码模块映射

### Desktop

| 文档 | 代码 | 状态 |
|---|---|---|
| `Desktop/Conversation/README.md` | `Desktop/src/Conversation/` | 单会话本地输入、事件与完成摘要 |
| `Desktop/TaskFlow/README.md` | `Desktop/src/TaskFlow/` + 阶段头部 | 可推进的内存 Workflow 与批准护栏 |
| `Desktop/Harness/README.md` | `Desktop/src/Harness/` | 只读导航 |
| `Desktop/README.md` | `Desktop/src/Layout/`、`Shared/` | 浅色响应式壳层、Copiner 品牌标记和展示契约 |

### CoreEngine

| 模块 | 责任 | 当前实现 |
|---|---|---|
| `workflow` | 强制闭环状态迁移 | 已测试完整路径和非法跳转 |
| `workflow_session` | 宿主可观察的单任务闭环 | 内存 snapshot、事件和下一动作 |
| `policy` | 数据敏感级别与 Provider 边界 | Unknown 默认拒绝 External |
| `provider` | Provider 描述、注册和选择 | 内存骨架，无真实模型 |
| `tool` | 权限、副作用、批准与注册 | 内存骨架，无执行器 |
| `harness` | Skill/Hook/Memory 元数据 | 内存骨架，无动态加载 |

### DesktopHost 与 Workspace

DesktopHost 启动 Tauri，并提供运行状态及本地 Harness 的创建、snapshot、推进和重置命令。会话仅存在内存，所有状态迁移由 CoreEngine 验证。WorkspaceService 的四项能力全部为 false；两者都不声称已连接真实模型或企业系统。

## Harness 渐进加载

```text
COWORK.md
├── 邮件任务 ─────────> Skills/Mail/SKILL.md
├── 问题单/审批 ───────> Skills/Ticket/SKILL.md
├── BIOS/BMC ─────────> Skills/BiosBmc/SKILL.md
└── 多分支同步 ────────> Skills/CodeSync/SKILL.md
                          └── 明确引用后才读 References/
```

`COWORK.md` 保持 30 行以内，SessionStart 动态来源放在 Hooks，重资料不进入每次会话基线。

## 当前阶段

当前是 M0/M1 工程框架：

- 已有可构建边界、统一入口、Workflow、安全策略和桌面本地可见闭环；
- Provider/Tool/Harness 有领域接口，但没有真实适配器或执行循环；
- Hook 只有 schema 和禁用示例；
- Workspace、RAG、企业系统、Memory Index 和桌宠均未实现。

完整编号、验收和进度见 `02-任务清单.md`。
