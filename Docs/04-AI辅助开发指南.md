# AI 辅助开发指南

本指南说明编码 Agent 如何取得最小必要上下文并安全完成 Copiner 任务。业务范围、技术选型和模块实景仍分别以 `02-任务清单.md`、`03-技术选型.md` 和模块 README 为准。

## 最小读取路径

```text
根 AGENTS.md
├── Docs/00-项目介绍.md
├── Docs/01-开发规范.md
├── Docs/02-任务清单.md（业务任务读取目标项）
├── COWORK.md（产品 Agent/Harness 任务）
└── 目标边界/AGENTS.md
    └── 目标模块/README.md 或 SKILL.md
```

不要无目的加载所有 References、Memory 或源码。先定位编号和目标模块，再读取直接依赖；路径和命令先用 `rg` / `rg --files` 验证。

## 任务决策

| 任务类型 | 行为 |
|---|---|
| 解释、审查、诊断 | 只读检查并给证据，不自动修改 |
| 单模块明确维护 | 列 Todos 后实施，运行模块验证并同步 README |
| 公共或跨边界改动 | 写 Plan，人工确认后实施，记录调用方/提供方和回滚 |
| 需求/架构/安全/选型/目录变化 | 先更新 Plan 或基线，经确认后执行 |
| 外部副作用 | Plan 确认后仍在动作发生前逐次批准 |
| 外部依赖缺失 | 记录阻塞，不用假数据、假接口或自选产品掩盖 |

## Harness 渐进读取

- 邮件：只读 `Skills/Mail/SKILL.md`；
- 问题单/企业流程：只读 `Skills/Ticket/SKILL.md`；
- BIOS/BMC：只读 `Skills/BiosBmc/SKILL.md`；
- 多分支同步：只读 `Skills/CodeSync/SKILL.md`；
- `References/` 仅在目标 Skill 明确指出具体文件时加载；
- `Memory/` 只读取任务必要且用户授权的条目。

## 标准 Todos 与 Plan

Todos 至少写清：里程碑编号、目标文件、预期行为、数据敏感级别、外部副作用、非目标和验证方式。

跨界 Plan 至少包含：背景、目标结构、实施顺序、公共契约、安全不变量、验证矩阵、回滚和待确认项。Plan 变化后重新确认。

## 验证矩阵

| 范围 | 最低证据 |
|---|---|
| Desktop | frozen install、typecheck、build、lint、consistency；UI 变化做浏览器/Tauri 实测 |
| CoreEngine | fmt、clippy、单元测试、workspace build |
| DesktopHost | Rust 全量验证；命令变化做实际调用或启动冒烟 |
| WorkspaceService | Rust 全量验证；网络变化做健康检查和目标请求 |
| Hooks/Skills/Memory | JSON 可解析、consistency、敏感示例人工核对 |
| 跨界契约 | 调用方和提供方均编译/测试，核对错误与拒绝态 |
| 根配置/CI | `make check` 或等价分栈命令 + `git diff --check` |

没有测试不等于可以不验证；至少完成编译、启动或可复现静态检查。工具缺失时明确列出未执行项。

## 交付格式

```text
结果：完成了什么
范围：修改的运行时、模块和公共契约
安全：敏感路由、审批和数据边界是否变化
验证：实际命令与结果
文档：同步的 README/任务项/技术决策
限制：未实现能力、外部依赖或风险
```

## 敏感数据

- 不向外部模型提供生产数据库、邮件正文、个人/客户信息、BIOS/BMC 原始敏感日志、Token、证书或私钥；
- 无法分类时按 Sensitive 处理；
- 测试夹具标注 synthetic 或 sanitized；
- 不把日志或截图中的敏感字段复制到 Issue、Plan 或提交信息；
- Agent 生成代码与人工代码采用同一验证标准，模型置信度不是证据。
