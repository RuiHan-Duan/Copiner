# 开发规范 — 运行时自治与安全边界

Copiner 以尽快交付可运行、可审阅且不越权的结果为目标。工程采用运行时边界自治、公共契约走 Plan、真实验证兜底。

## 改动分级

### A. 只读任务

解释、审查、诊断和状态报告可直接检查并给出证据，不创建 Plan，也不自动修复。

### B. 单模块明确维护

同时满足以下条件可列 Todos 后实施：

- 属于 `02-任务清单.md` 现有范围或不改变产品能力的工程维护；
- 只修改一个模块，不改变公共契约、安全策略、依赖、目录、构建或 CI；
- 执行目标边界的真实验证；
- 同步目标模块 README。

### C. 公共或跨界改动

以下任一情况必须执行 Clarify → Todos → Plan → Confirm → Execute → Feynman → Archive：

- 同时修改两个以上运行时边界；
- 改变 Workflow、Provider、Tool、Hook 或 Memory 公共契约；
- 修改敏感路由、动作审批、鉴权、密钥或审计策略；
- 修改根 Cargo workspace、依赖、锁文件、目录、Makefile、`build.ps1` 或 CI；
- 修改 `02-任务清单.md` 或 `03-技术选型.md`。

### D. 外部副作用

发送/转发邮件、提交/关闭问题单、批准电子流、push/merge 代码、删除外部数据等动作，必须在发生前展示具体目标、参数和影响并逐次确认。已确认 Plan 只授权进入 Execute，不是永久动作授权。

## 跨界工作流

1. **Clarify**：确认目标、范围、敏感级别、外部依赖、验收和非目标。
2. **Todos**：每项写清编号、目录、预期行为、边界外内容和验证方式。
3. **Plan**：在 `Plans/` 记录实施顺序、风险、安全约束和回滚。
4. **Confirm**：用户明确确认后才修改跨界代码；Plan 变化后重新确认。
5. **Execute**：保持小而可回滚，外部动作仍需动作级批准。
6. **Feynman**：用用户熟悉的语言解释结果、限制和验证证据。
7. **Archive**：更新 README、任务进度和 Plan 验收；RAG 未实现前只归档文本。

## 分层规则

- Workflow、路由和审批规则优先放 `CoreEngine`；
- Desktop 只展示状态，DesktopHost 只转换命令和系统能力；
- WorkspaceService 不反向依赖 Desktop，不自行决定业务规则；
- Provider、Tool、Skill 通过接口或注册表扩展，厂商细节不能进入状态机；
- `Shared`/公共导出保持小而稳定，避免把占位接口冻结为最终契约。

## 数据与安全

1. Unknown 按 Sensitive 处理，只允许 Local/Enterprise Provider。
2. 无真实数据时展示空态，不使用随机数或硬编码业务指标。
3. 测试样例标记 synthetic 或 sanitized，不提交生产内容。
4. 密钥从环境或系统密钥链读取，不提交 `.env`、Token、Cookie、证书和私钥。
5. Memory 正文可审阅、可迁移、可删除；敏感内容默认不外部同步。
6. 日志和错误不得泄漏任务正文、密钥或企业字段值。

## 命名约定

- 顶层和产品模块目录使用 PascalCase：`Desktop/`、`TaskFlow/`；
- Rust crate 目录沿用 PascalCase，crate/module/文件遵循 Rust snake_case；
- Vue 组件 PascalCase，TypeScript 文件 kebab-case 或项目现有一致形式；
- Skill 目录 PascalCase，入口固定 `SKILL.md`；
- Plan 使用 `YYYY-MM-DD-主题.md`。

## 文档同步

- 需求是否完成只在 `02-任务清单.md` 判断；接口占位不等于能力完成；
- 模块 README 描述职责、当前实景、主要文件、扩展边界和限制；
- 技术版本、构建入口和暂缓选型写入 `03-技术选型.md`；
- 跨界 Plan 执行后追加真实命令结果，不删除历史记录；
- 目录、依赖、构建和公共契约变化按根 AGENTS 文档影响矩阵同步。

## 验证矩阵

| 范围 | 最低验证 |
|---|---|
| Desktop | frozen install、typecheck、build、lint、consistency；交互改动实测 |
| CoreEngine | fmt、clippy、目标单测、workspace build |
| DesktopHost | Rust 全量验证；命令变化做 Tauri 启动/调用冒烟 |
| WorkspaceService | Rust 全量验证；网络服务变化做健康检查和请求 |
| Harness 文本/schema | consistency、JSON 解析、敏感样例检查 |
| 根配置/CI | 全量 check + `git diff --check` |

## 完成定义

- 用户可观察目标已实现，失败态和安全拒绝可复现；
- 与范围相称的 build/test/lint/运行检查真实通过；
- 无密钥、生产数据、生成物和伪造结果入库；
- 文档与代码实景一致，完整能力才勾选任务项；
- 变更可独立回滚，已知限制明确记录。

Agent 的说明或置信度不能替代命令输出。工具缺失时记录阻塞，不写成通过。
